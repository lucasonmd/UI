# HMI 화면설계서 도구 (`hmi-designer-v2.html`)

| 파일 | 내용 |
|---|---|
| **`hmi-designer-v2.html`** | 최신판. UI 정리판 — 보기/편집 스위치, 트리 추가 버튼 줄·화면 수, 도구줄 토글 칩 등 |
| `hmi-designer.html` | 바로 이전 판 (비교용으로 남겨 둠) |

v2 는 v1 저장본을 그대로 연다(전시기 2개로 자동 변환). 반대로 v1 은 전시기가 들어간 v2 저장본(schema 3)을 읽지 못한다. 화면 안의 `DESIGN 1/2/3` 는
HMI 화면 디자인 전환이고, 파일 버전(v2)과는 별개다.

PPT로 관리하던 GUI 설계자료를 HTML로 옮기기 위한 도구. **파일 하나가 편집기이자
뷰어이자 산출물이다.** 더블클릭하면 열리고, 저장하면 설계 데이터가 박힌 HTML 한
장이 나오며, 그 HTML을 다시 열면 이어서 편집된다. 설치·빌드·서버 없음.

```
hmi-designer.html          도구 (빈 데이터 + 예제 문서)
  └ 저장 →  우리체계_화면설계서.html      도구 + 데이터 (이걸 주고받는다)
              └ 다시 열기 → 편집 계속
```

## 1. 두 가지 모드

| | 보기 모드 (기본) | 편집 모드 (<kbd>E</kbd>) |
|---|---|---|
| 용도 | **발표·검토용** | 작성용 |
| 화면 | 1920×1080 비율 고정, 창에 맞춰 축소 — **항상 전체가 보인다** | 〃 |
| 이동 | 화면 속 소프트키 클릭 · 키보드 <kbd>F1</kbd>~<kbd>F20</kbd> · 기능영역 라벨 · 트리 | 〃 |
| 크기 | 위 **목록/설명** 을 끄면 화면이 커진다 · **전체 화면** 버튼 · <kbd>Ctrl</kbd>+휠 확대 · <kbd>Ctrl</kbd>+<kbd>0</kbd> 맞춤 | 〃 |
| 강조 | 설명 항목이나 요소에 올리면 그 요소에 **얇은 흰 윤곽 + 옅은 빛**, 누르면 파란 윤곽으로 고정(다시 누르면 해제). 주변은 어둡게 하지 않는다 | 얇은 파란 윤곽 |
| 패널 너비 | 메뉴 트리 · 화면 · 설명 패널 사이 **경계를 끌어** 너비 조절(트리 180~560, 설명 280~760, 화면은 최소 420 유지). 경계를 **두 번 누르면 기본값**. 브라우저에 기억되고 문서에는 저장되지 않는다 | 〃 |
| 캔버스 | 1920×1080 뒤는 흰색. 위쪽 **검은 배경** 을 켜면 검정(브라우저에 기억됨) | 〃 |
| 디자인 | 전시영역 **좌측 하단의 흐린 `DESIGN 1/2/3`** 을 누를 때마다 1→2→3→1 로 전환. 3 = 그린 콘솔 — 순검정 바탕에 녹색 면 키·흰 고정폭 굵은 글씨, 선택은 노란 테두리, 상태바 값은 녹색·알림 줄은 호박색, 패널은 짙은 녹색 면+녹색 테두리. 2 = 전술 콘솔(고대비) — 순검정 바탕·흰 굵은 글씨, 선택은 색 반전, 2px 테두리 키, 옅은 전술 격자, 입체감·모서리 장식 없음. 문서에 저장되어 인쇄·발표에도 따라간다 | 〃 |
| 오른쪽 | 읽기 전용 **설명판** (아래 §3) | 입력 폼 4개 탭 |
| 편집 도구 | 전부 숨김 — 입력칸 자체가 렌더되지 않는다 | 트리 추가/삭제, 그림 넣기, 스냅, 실행취소 … |

화면 **아래에는 아무것도 두지 않는다.** 1920×1080 전체가 항상 보여야 하므로
설명은 전부 오른쪽 패널로 모았다.

문서를 열었을 때의 기본 모드는 **코어 탭 → 문서 정보 → 열 때** 에서 정한다.

## 1-1. 전시기 (승무원 임무) 탭

승무원 임무에 따라 **임무전시기**(차장·포수)와 **운용전시기**(조종수)는 메뉴와 구성이
다르다. 화면 위의 **탭**으로 둘 사이를 오간다.

- 전시기마다 따로: **화면 트리 전체**, **기능영역 8개의 사용 여부·설명**
- 모든 전시기가 함께: **Core**(치수·상태바·팔레트), 문서 정보, 그림 저장소
- **+ 전시기**: 새 전시기를 추가한다. *확인*을 누르면 지금 전시기를 복사하고,
  *취소*를 누르면 초기화 템플릿으로 시작한다. 복사본의 화면 id 는 새로 매겨지므로
  원본을 고쳐도 복사본은 바뀌지 않는다
- 편집 모드: 탭을 **더블클릭**하면 이름을 바꾸고, **✕** 로 삭제한다(마지막 1개는 못 지움).
  *코어* 탭의 **전시기 (승무원 임무)** 칸에서 이름·코드(CrewRole)·설명도 고친다
- 인쇄/PDF 는 **모든 전시기**를 차례로 찍는다. 목차에 전시기별로 묶이고, 각 화면 머리 경로에 전시기 이름이 붙는다
- 전시기 추가·삭제·이름 변경도 Ctrl+Z 로 되돌린다
- **화면 ID 와 동기화** — 화면마다 ID(화면 탭 → 기본 → *화면 ID*)가 있다
  · **복제**, *다른 전시기로 복사*, *전시기 추가(복사로 시작)* 는 ID 를 그대로 가져간다 →
    ID 를 바꾸기 전까지 같은 ID 화면들은 **모든 전시기에 걸쳐 내용이 같이 바뀐다**
  · 같이 바뀌는 것: 제목·그림(배치 포함)·요소·F1~F12·F13~F20 비고·설명·상태바·변경 이력.
    따로인 것: 트리 위치(상위 화면·진입 키)·기능영역·특수 화면 구분
  · 묶임 정보는 **편집 모드의 화면 탭에만** 보인다(어느 전시기의 어느 화면과 묶였는지). 보기 모드·메뉴 트리에는 나오지 않는다
  · 끊기: ID 를 새로 쓰거나 **동기화 끊기 (새 ID)**. 다른 화면의 ID 를 쓰면 그 묶음에 들어가고
    이 화면 내용은 그쪽 내용으로 바뀐다(확인 창)
  · 새로 만든 화면은 `SCR-001` 식 새 ID 를 받는다
  · 예전 파일: ID 가 없으면 전시기끼리 제목 경로·내용이 같은 화면에 같은 ID 를 준다.
    같은 ID 인데 내용이 이미 다른 화면은 덮어쓰지 않도록 새 ID 로 나눈다
- **화면을 다른 전시기로 보내기** (편집 모드)
  · 화면 탭 → **다른 전시기로 보내기** → 보낼 곳 고르고 **복사** / **이동**
  · 또는 왼쪽 트리에서 화면을 위쪽 **전시기 탭**으로 끌어다 놓기 (놓으면 이동, <kbd>Ctrl</kbd> 누르고 놓으면 복사)
  · 하위 화면까지 통째로 간다. 그쪽에 같은 상위 화면(제목 경로)이 있으면 그 밑에(같은 F키, 차 있으면 빈 키),
    없으면 같은 기능영역의 최상위 화면이 된다. 알람·위협·Core 특수 화면은 그쪽에 이미 있으면 보통 화면으로 들어간다
  · Ctrl+Z 로 되돌린다
- 예전 파일(schema 2 이하)을 열면 기존 화면은 임무전시기로 들어가고,
  운용전시기는 그 **복제본**으로 자동 생성된다. 운용전시기에서 필요 없는 화면은 지우고,
  기능영역 사용 여부만 끄면 된다

## 2. GVA 구조 (이 도구가 강제하는 규칙)

도구가 규칙을 지키게 해서 설계서와 실제 동작이 어긋나지 않게 했다.

### 2.1 기능영역 8개 = Application 8개

상단 베젤 물리 버튼 **SA · WPN · DEF · SYS · DRV · STR · COM · BMS**
(상황인식 · 무장 · 방호 · **설정** · 주행 · **특수** · 통신 · 전장관리). **기능영역
1개에 HMI Application 1개가 1:1로 대응**한다. 그래서 이 도구에서는:

- **최상위 화면에 기능영역을 지정한다** → 그 기능영역 Application 의 루트 메뉴가 된다
- 하위 화면은 기능영역을 자동으로 물려받는다
- 화면 안의 **기능영역 라벨 8개**(6px 트랙 바) 상태가 **자동 계산**된다 —
  현재 기능영역 = 선택, 미운용 기능영역 = 비활성. 트랙 바 반쪽만 칠하는
  `SelectedLeft`/`SelectedRight` 가 필요할 때만 화면별로 직접 지정한다
- 보기 모드에서 그 라벨을 누르면 해당 기능영역의 최상위 화면으로 간다
  (왼쪽 트리의 기능영역 머리, 오른쪽 설명판의 기능영역 항목도 같은 동작)
- **Core 영역 구성** 화면은 비어 있는 F1~F12 를 `GVA.F1` ~ `GVA.F12` 라벨로 보여 준다(자리 표시 —
  설명판·인쇄의 소프트키 목록에는 넣지 않는다)
- **미실행 Application** : 그 전시기에서 실행되지 않는 기능영역은 라벨이 비활성으로 그려진다.
  설정하는 곳(편집 모드, 셋 다 같은 값이며 **전시기마다 따로**):
  1. 왼쪽 트리 기능영역 머리의 **실행 / 미실행** 버튼 — 누를 때마다 바뀐다
  2. 화면 탭 → 기본 → *이 전시기에서 실행* 체크 (지금 화면의 기능영역)
  3. 코어 탭 → 기능영역 8개 표의 **사용** 체크
- 왼쪽 트리도 기능영역으로 묶인다

### 2.2 화면 이동은 F1~F12 로만

F1~F12 를 누르면 그 키에 배정된 **하위 화면**으로 내려간다. 그래서 **메뉴 트리 =
F1~F12 배정표**이고, 깊이 제한이 없다. F1~F12 가 전부 이동은 아니다:

| 역할 | 뜻 | 설정 |
|---|---|---|
| 이동 | 하위 화면으로 내려간다 | 그 키에 하위 화면을 만들면 **자동**으로 이동 키가 된다 |
| 명령 | 동작을 실행한다 (BIT 실행, 저장 …) | 역할을 "명령"으로 두고 설명을 적는다 |
| 상태 | 선택 상태를 표현한다 (야간 모드 …) | 역할을 "상태"로 두고 상태를 `선택`으로 |

상태는 SoftButton 규격 그대로 **활성 / 선택 / 비활성 / 숨김** 4가지다. 라벨이 비어
있으면 자동으로 **숨김**(자리까지 사라짐)이 된다. 작성 중에 숨긴 키 자리를 보려면
상단 **숨김키** 를 켠다.

### 2.3 F13~F20 은 GVA 규정 공통 버튼

라벨·기능이 화면마다 바뀌지 않는다. 화면별로는 **상태와 비고만** 적는다.

| 키 | 라벨 | 기능 | 도구 동작 |
|---|---|---|---|
| F13 | UP | 메뉴 구조에서 한 단계 위로 | **상위 화면으로 이동**. 물리 버튼이라 **항상 활성**으로 표기 |
| F14 | ALARMS | 현재 모든 System Alert 표시 | **알람 화면으로 이동** |
| F15 | THREAT | 현재 모든 Threat 표시 | **위협 화면으로 이동** |
| F16 | ACK | Warning/Alarm 확인 | 명령 |
| F17 / F18 | ▲ / ▼ | 메뉴 스크롤·값 증감 | 명령 |
| F19 | LABELS | 베젤 라벨 표시/숨김 | 명령 |
| F20 | ENTER | 입력 확정 / 선택 메뉴 실행 | 명령 |

F14·F15 목적지는 **화면 탭 → 특수 화면**에서 지정한다. 없으면 자동 비활성.

### 2.4 Application 영역 안은 이동 수단이 아니다

그림·요소는 번호와 설명이 붙는 설명 대상일 뿐이다(요소에 링크 기능이 없는 이유).

### 2.5 StatusBar

**코어 탭 → 상태바 기본값**에서 편집한다(화면별로 다르게 하려면 화면 탭 → 상태바).

| 줄 | 구성 |
|---|---|
| 1줄 | `TIME` · `HDG` + **커스텀 전시정보 (개수 자유)** |
| 2줄 | `POS` + `ALERT`(등급 3px 선 · 시각 · 문구 · 건수 뱃지) + `WARN`/`CAUT`/`IGN` 집계 |

커스텀 전시정보는 기본 **8칸**(임무·모드·위성항법·통신·무장·전원·연료·승무원)이고, **+ 항목 / ✕ 로 개수를 마음대로** 늘리고 줄인다. 칸마다
이름 · 값 · 색 · **비율**을 갖는데, 이 비율이 실기 `StatusBarViewModel.
LoadCustomDisplayData` JSON 의 `itemWithLayout` Ratio 에 해당한다(칸이 차지하는
가로 비율). **비율 균등** 버튼으로 전부 1 로 되돌릴 수 있다.

## 3. 오른쪽 설명판 (보기 모드)

절(section) 단위로 쌓이고, **창 높이에 안 들어가면 자동으로 `1 / 3` 처럼 나눠서**
아래 페이저로 넘긴다(<kbd>PageUp</kbd>/<kbd>PageDown</kbd>).
화면 속 요소를 누르면 그 설명이 있는 쪽으로 **자동으로 넘어가** 해당 항목이 강조된다.

1. **개요** — 제목·기능영역·화면 ID·경로·요약
2. **F1~F12 소프트키** — 라벨, 구분(이동/명령/상태), 상태, 설명, 이동 대상.
   항목을 누르면 그 화면으로 이동하고, 올려놓으면 화면 속 해당 키가 강조된다
3. **화면 요소** — 번호별 명칭·설명 (올려놓으면 화면에서 해당 영역 강조)
4. **설명** — 상세 서술
5. **기능영역** — SA~BMS 8개와 현재 상태
6. **F13~F20 공통 버튼** — 상태와 기능
7. **변경 이력**

## 4. 설명 페이지 (자유 양식)

트리의 **+ 설명** 으로 추가한다. PPT 새 슬라이드처럼 **HMI 틀 없이** 1920×1080 전체에 텍스트·표·그림·박스를
자유롭게 올리는 페이지다 — 표지, 개요, 용어 정리, 흐름도 같은 것에 쓴다.

- 제목·본문 칸이 미리 깔려 있고, 글은 *요소* 탭에서 고친다. 배경은 흰색/어두운색
- 그림을 붙여넣으면 페이지 전체 배경이 된다. **그림 조정**으로 1920×1080 안 어디에든 옮기고 키우고 자를 수 있다
- 소프트키·기능영역이 없고, 오른쪽 설명판에는 요약과 **발표 메모**가 나온다

페이지 순서(트리 · 인쇄 · <kbd>←</kbd>/<kbd>→</kbd> 넘김 모두 같다):
**설명 페이지 → 공통 화면(Core 영역 설명 · 알람 · 위협) → 기능영역(SA~BMS) 순서**

## 4-1. 특수 화면

**화면 탭 → 특수 화면** 에서 지정한다.

| 종류 | 쓰임 |
|---|---|
| Core 영역 설명 | 요소 좌표가 **1920×1080 전체 기준**이 되어 StatusBar·레일·기능영역 라벨·Application 영역까지 번호를 달아 설명할 수 있다. 예제 문서 첫 화면이 이것이다 |
| F14 알람 화면 | 어느 화면에서나 F14 로 진입 |
| F15 위협 화면 | 어느 화면에서나 F15 로 진입 |

보통 화면의 요소 좌표는 **Application 영역(1590×915) 기준**이다.

### F14 알람 화면 (Alarm Register)

`GVA Alarms Service Specification v3.0` 의 Alarm Register 를 기준으로 기본 화면과 설명을 넣어 두었다.
**등급은 경고(W)·주의(C) 두 가지만 쓴다** — 자문(Advisory)은 이 체계에서 쓰지 않는다.

| 항목 | 내용 |
|---|---|
| 등록부 표 | 발생 시각 · 알람 내용 · 등급(W/C) · 상태 |
| 상태 값 | `UNACK` 미확인 · `ACK` 확인 · `RES` 해소 · `OVR` 무시 설정 · `ACT` 조건 활성 |
| 색 | 활성 = 등급색(경고 적 · 주의 황) · 무시 설정 = 회색 · 해소 = 흰색 |
| 알림 방법 | 경고 = 텍스트 메시지 + 음향 + 등록부 / 주의 = 텍스트 메시지 + 등록부(음향 없음) |
| 텍스트 메시지 | 상태바 바로 아래 **한 번에 한 건**, 경고만 점멸. 대기 중인 알람 수를 함께 표시 |
| 소프트키 | F1 정렬(시각↔등급) · F2 순서(내림↔오름) · F3 무시만 보기 · F7 전체 선택 · F8 지우기 · F9 무시 설정 · F12 주석 추가 |
| 확인(ACK) | 등록부에서 하지 않는다. F16 은 **지금 떠 있는** 알람 메시지를 확인 처리한다 |
| 권한 | 무시 설정은 주의(C)만(경고는 불가) · 지우기는 차장=해소된 알람만, 정비=모든 상태 |

이 구성은 **초기화 템플릿과 예제 문서**에 들어 있다. 이미 저장해 둔 파일에는 반영되지 않으므로,
필요하면 그 파일의 알람 화면을 직접 고치거나 초기화 후 옮겨 붙인다.

## 5. 쓰는 순서

1. **편집**(<kbd>E</kbd>)을 켠다
2. 트리의 **기능영역 머리(SA~BMS) 옆 `+`** 로 그 영역의 최상위 화면을 만든다
   (화면이 하나도 없는 기능영역도 머리와 `+` 가 보인다. 상단 **+ 최상위** 는 지금 보는 화면의 기능영역에 만든다)
3. **+ 하위** — 비어 있는 F1~F12 중 하나가 자동 배정된다
   (특정 키에 달려면 **소프트키** 탭에서 그 키의 *이 키에 하위 화면 만들기*)
   **구조 옮기기** — 트리에서 끌어다 놓는다:
   · 다른 화면 위에 놓기 → 그 화면의 하위로(빈 F 키 자동 배정)
   · 기능영역 머리나 "화면 없음" 칸에 놓기 → 그 기능영역의 **최상위**로
   · 드래그 없이 하려면 화면 탭 → **상위 화면** 선택칸에서 고르거나 `(최상위)` 선택
   하위 화면들은 함께 따라 옮겨진다
4. 화면 내용을 채운다
   - **캡처** : <kbd>Ctrl</kbd>+<kbd>V</kbd> · 이미지 파일 끌어놓기 · 상단 **그림 넣기**
     — **1920×1080 전체 화면 캡처는 Application 자리(165,105)가 겹치도록 놓인다.** 원본은 자르지 않고
     그대로 보관하므로 나중에 얼마든지 옮기고 키울 수 있다. 끄려면 화면 탭 → 화면 그림의 체크 해제
   - **그림 조정** : 도구줄 **그림 조정**(또는 화면 탭 → *화면에서 조정*)을 누르면 그림에 손잡이가 붙는다
     · 끌기 = 이동, 모서리 = 크기(비율 유지, <kbd>Shift</kbd> 자유), 가장자리 = 한 방향만
     · 휠 = 커서 기준 확대·축소(<kbd>Shift</kbd> 미세), 방향키 1px / <kbd>Shift</kbd> 10px
     · <kbd>C</kbd> 또는 *자르기* = 그림은 그대로 두고 보이는 가장자리만 줄인다(점선 틀). 가린 부분은 흐리게 보인다
     · 영역 가장자리·가운데·요소 모서리에 달라붙는다(<kbd>Alt</kbd> 누르면 안 붙음). <kbd>Esc</kbd>/<kbd>Enter</kbd> 끝
     · 한 번에 맞추기: 전체 보이기 · 꽉 차게(잘림) · 늘려 채우기 · 원본 크기 · 폭 맞춤 · 높이 맞춤 · 가운데로 · 전체 캡처 정렬
     · 숫자로: X·Y·폭·높이·배율 %·불투명 %·자르기 % (비율 고정 선택)
     · **보이는 부분만 남기기** = 영역 밖·가린 부분을 버리고 새 그림으로 굽는다(파일 용량 줄이기, Ctrl+Z 로 원본 복구)
     · **자유 배치 해제** = 예전처럼 영역 전체에 맞춤(꽉 채움·비율 유지·잘라 채움)
   - **직접 그리기** : 화면 위를 드래그 (요소 종류는 *요소* 탭에서 선택)
   - **섞어 쓰기** : 캡처 위에 **영역** 요소를 얹으면 번호와 설명만 달린다
5. **소프트키** 탭에 F1~F12 라벨·역할·설명과 F13~F20 상태를 적는다
6. **저장** → 데이터가 들어간 HTML 한 장. 다시 열면 이어서 편집된다

처음부터 다시 만들려면 상단 **초기화**(편집 모드) — 기본 템플릿으로 돌아간다. 템플릿에는 **필수 화면**
(Core 영역 설명 · F14 알람 · F15 위협)과 **기능영역 기본 화면 6개**(SA · WPN · DEF · SYS · DRV · BMS 메인)가 들어 있다. 바로 <kbd>Ctrl</kbd>+<kbd>Z</kbd> 로 되돌릴 수 있다.
필수 화면 정의는 `coreIntroPage()` / `alarmPageTpl()` / `threatPageTpl()`, 기능영역 기본 화면은 `areaHome()` 한 곳에 있고 예제와 템플릿이 같이 쓴다.
7. **인쇄 / PDF**(<kbd>Ctrl</kbd>+<kbd>P</kbd> → 대상 *PDF로 저장*) — A4 가로, **화면 하나 = 1쪽**(내용이 많으면 이어지는 쪽)
   - 모든 쪽 고정 요소: **왼쪽 위 문서 제목**(헤더의 제목 칸 = `meta.title`) · **오른쪽 아래 쪽 번호** `n / 전체`
   - 구성: 표지(제목·체계명·개정·일자·전시기) → 목차(쪽·전시기·기능영역·화면·진입 키) → 화면 쪽들
   - 화면 쪽: 경로(전시기 › 기능영역 › 상위 화면) · 화면 제목 · 화면 그림(폭 790px) ·
     그 아래 2단으로 **화면 설명**(요약 + 상세 + **번호별 요소 설명** — 화면 속 번호와 같은 번호),
     오른쪽에 **F1~F12 중 실제로 있는 키만**(라벨·이동/명령/상태·비활성 여부·설명·→ 이동할 화면)
   - **Core 영역 설명** 화면만 예외 — 요소 설명이 곧 내용이라 오른쪽 칸에 넣는다(소프트키 자리)
   - 화면 속 번호 동그라미는 속을 거의 투명하게 두고 흰 테두리·검은 그림자로 읽히게 했다(화면을 가리지 않게)
   - 넣지 않는 것: F13~F20 공통 버튼, 변경 이력
   - 설명 페이지는 슬라이드를 본문 폭 가득 찍는다(발표 메모는 빼고)
   - **한 쪽에 안 들어가면 글자를 줄이지 않고 "이어서" 쪽으로 넘긴다.** 설명은 줄·요소 단위,
     소프트키는 키 단위로 넘어가며, 이어지는 쪽에도 같은 화면 제목과 *이어서* 표시가 붙는다.
     목차 쪽 번호는 나눠진 결과를 반영해 매겨진다
   - 인쇄 대화상자에서 여백은 *기본값*(=@page 0) 그대로, *배경 그래픽* 은 켠다

요소 배치: 끌면 다른 요소·영역의 **가장자리와 중앙선에 자동으로 달라붙고** 파란 안내선과
좌표가 뜬다. 여러 개를 고르면(<kbd>Shift</kbd>+클릭) *요소* 탭에 왼쪽/오른쪽/위/아래 맞춤,
가로·세로 가운데, 너비·높이 통일, 간격 균등이 나온다.

## 6. 데이터 구조

저장본 안 `<script id="hmi-data" type="application/json">` 한 덩어리가 전부다.
JSON만 빼려면 *코어* 탭 → **JSON만 내보내기**.

```jsonc
{
  "schema": 3,
  "meta": { "title", "system", "author", "rev", "date", "openMode": "view|edit" },
  "core": {
    "screen": {"w":1920,"h":1080},
    "app":    {"x":165,"y":105,"w":1590,"h":915,"margin":4,"radius":14},
    "status": { "time","hdg","pos",
                "custom":[{n,v,t,r}], "alert":{level,time,msg,count}, "tally":{warn,caut,ign} },
    "labels": {"x":165,"y":79,"w":183,"h":20,"pitch":201,"count":8},
    "side":   {"w":153,"h":100,"top":84,"pitch":167.2,"count":6,"leftX":0,"rightX":1767},
    "bottom": {"x":33,"y":1028,"w":214,"h":48,"pitch":234.29,"count":8,"labels":{"F13":"UP",…}},
    "theme":  { "void":"#000000", … }
  },
  "assets": { "i0a1b2": "data:image/jpeg;base64,…" },
  "roleId": "rMission",                             // 마지막으로 보던 전시기
  "roles": [{                                       // 전시기(승무원 임무)마다 하나
    "id":"rMission", "name":"임무전시기", "code":"Mission", "desc":"…",
    "areas": [ { "key":"SA", "name":"상황인식", "use":true, "desc":"…" }, … 8개 ],
    "pages": [ …아래 화면 구조… ]
  }, { "id":"rOper", "name":"운용전시기", "code":"Operation", … }]
}
// roles[].pages 한 항목:
{
    "id","title",
    "parent": "<상위 화면 id>", "viaKey": "F3",     // 트리 = F1~F12 배정
    "area": "DRV",                                  // 최상위 화면에만. 하위는 물려받는다
    "sys": "" | "core" | "alarm" | "threat" | "doc",
    "kind": "mock|image", "image": "a:i0a1b2 | img/drv.png", "imgFit",
    "imgBox": null | { "x","y","w","h", "crop":[위,오른쪽,아래,왼쪽 (0~1)], "op":1 },  // 그림 자유 배치. null 이면 imgFit
    "desc","notes","hist":[{d,w,t}],
    "elements":[{ "id","type","name","rect":[x,y,w,h],"desc","props":{},"doc" }],
    "keys":   { "F1": {"label","role":"nav|cmd|state","state","desc"} },   // F1~F12
    "bottom": { "F17": {"state","desc"} },                                 // F13~F20 상태·비고만
    "labels": { "0": {"s":"selectedLeft","desc":"…"} },                    // 비우면 자동 계산
    "status": null                                                         // 화면 전용 상태바 값
}
```

- 편집 중에는 `S.doc.pages`/`S.doc.areas` 가 지금 전시기 배열을 가리키는 별칭이다
  (`bindRole`). 저장할 때 `syncRole` 로 되돌려 쓰고 최상위에서는 빼므로 저장본에는 `roles` 안에만 있다
- `rect` 는 보통 화면이면 **Application 영역 기준 px**, `sys:"core"` 면 **1920×1080 기준 px**
- `doc:false` 인 요소는 번호와 설명표에서 빠진다(배경용 상자 등)
- `keys[Fn].label` 을 비우면 **하위 화면 제목**을 라벨로 쓴다 → 제목만 고치면 둘 다 바뀐다
- 하위 화면이 달린 키는 `role` 을 뭐라 적든 **이동**으로 취급된다

## 7. 어디를 고치면 무엇이 바뀌나

| 하고 싶은 것 | 고칠 곳 |
|---|---|
| **요소 종류 추가** (예: 게이지) | ① `TYPES` 에 한 줄 (`f` 가 입력칸을 자동 생성) ② `PROP_DEFAULT` ③ `elBody()` 렌더 분기 ④ CSS `.w-…` |
| 기능영역 이름·개수 변경 | `areasDefault()` (+ `core.labels.count`) |
| F13~F20 기능·라벨 규격 변경 | `GVA_BOTTOM` 한 곳 (도구 동작은 `nav` 필드로 연결) |
| Core 치수·팔레트 변경 | `coreDefault()` / `THEME_DEFAULT` — WPF 쪽 `CoreUiBuilder.cs`·`GvaColors.xaml` 과 같은 값을 유지할 것 |
| 상태바 항목 구성 변경 | `statusHTML()` + `statusFields()` (둘이 짝) |
| 발표용 설명판 절 추가 | `viewPanel()` 에 `vsec(제목, 내용)` 한 줄 — 페이지 나눔은 자동 |
| 속성 패널에 입력칸 추가 | `fld(라벨, '경로', 종류, 값)` 한 줄. 경로 첫 마디는 `doc`/`core`/`areas`/`page`/`el` |
| 버튼 동작 추가 | `ACTS` 에 함수 하나 + HTML에 `data-act="이름"` |
| 인쇄 레이아웃 | JS `buildPrint()`(표지·목차·쪽 번호) · `prScreenBody()`(화면 쪽) · `prDesc()`(설명+요소) · `prKeys()`(F1~F12) · `splitPrint()`(넘치면 이어지는 쪽으로), 장 크기 `SHEET` 1122×793, 화면 그림 폭 `PR_SHOT_W`. CSS `[9] 인쇄 / PDF` 블록(`--pr-*` 색 변수) |
| 옛 파일 호환 | `normalize()` — 빠진 필드를 채우는 **유일한** 지점 |
| 디자인 버전 2 | CSS `[5-2]` 블록 (`.screen.v2 …`) 한 곳. 켜고 끄는 값은 `meta.design` |
| 디자인 버전 3 | CSS `[5-3]` 블록 (`.screen.v3 …`) 한 곳. 색은 맨 위 `--v3-*` 변수만 고치면 전체가 따라간다. `meta.design` = `v1`/`v2`/`v3` |
| 그림 자유 배치 | JS `[5-9]` 블록 (`imgTag` 그리기 · `startImgDrag` 끌기 · `boxFor` 맞춤 계산 · `imgPanel` 오른쪽 칸 · `bakeImg` 굽기). 조정 틀 모양은 CSS `.imgedit` / `.ihnd` |
| 글꼴 | 문서 UI = Pretendard, 고정폭 = Consolas + **D2Coding**(한글). 디자인 2 화면 = 한글·제목·키 Pretendard / 숫자·상태값 D2Coding. 둘 다 CDN, 오프라인이면 맑은 고딕·Consolas. 디자인 3 화면 = 전부 D2Coding. 디자인 1 화면은 WPF 와 같은 Segoe UI·맑은 고딕 |
| 문서 UI 색 | `:root` 의 `--gray1~12` / `--blue1~12` — [Radix Colors](https://www.radix-ui.com/colors) Slate·Blue. **선택·주요 버튼은 9단계로 칠하지 않고** 3~5단계 옅은 배경 + 11단계 글자 + 7단계 테두리. HMI 화면 색(`--hmi` 등)은 WPF 쪽 값이라 별개 |

설계상 지켜야 할 것:

1. **화면 렌더는 `screenHTML()` 하나뿐이다.** 스테이지도 인쇄도 이걸 쓴다.
2. **저장본 = `SRC`(스크립트 시작 시점의 원본 HTML) + 데이터.** CSS/JS를 고치면 다음
   저장본부터 자동 반영된다. `SRC` 는 스크립트 맨 첫 줄에서 옮기지 말 것.
3. **트리 = 기능영역 + F1~F12 배정**(`area` + `parent` + `viaKey`). 따로 두지 말 것.
4. **기능영역 라벨 상태는 계산 결과다**(`effLabel`). 화면마다 손으로 적게 하지 말 것.

## 9. 알려진 제약

- 같은 파일 덮어쓰기는 Chrome / Edge 에서만 된다. 그 외 브라우저는 다운로드 폴더로 떨어진다
- 저장할 때 어느 화면에서도 쓰지 않는 그림은 자동으로 빠진다
- 실행취소 40단계. 내장 그림 삭제는 실행취소 대상이 아니다(메모리 보호)
- 캡처를 내장하면 파일이 커진다. 폭 1920px 초과분은 자동 축소되지만, 화면이 수십 장이면
  `img/…` 외부 경로 방식이 낫다(대신 HTML 한 장만 보내면 그림이 빠진다)
- 한 화면의 하위 화면은 최대 12개다(F1~F12). 규격상 더 늘릴 수 없다
